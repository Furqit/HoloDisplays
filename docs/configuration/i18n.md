# Translations (i18n)

All player-facing text (command feedback and GUI screens) is resolved from language files, server-side. No client mod or resource pack is needed.

## Language files

Files live in `config/holodisplays/lang/<locale>.json`, named after the client language code (`en_us`, `zh_cn`, `de_de`, ...). The mod writes a bundled `en_us.json` there on first start; that file is the complete key list.

Each player sees the language their client uses, with English as the fallback for unsupported locales or missing keys. Console and non-player command sources always get English.

## Adding a translation

Copy `en_us.json` to a new file named after the locale, translate the values, then run `/holodisplays reload`.

* Never rename keys, and keep `{placeholders}` such as `{name}` or `{page}` intact; they can be moved freely inside the sentence.
* Keep the `§` formatting codes in the `prefix` value.
* Names and registry IDs (e.g., `minecraft:zombie`) stay as-is.
* Enum values shown next to `Current` in GUI tooltips (`billboardMode`, `alignment`, `itemDisplayType`, `pose`) can optionally be translated, e.g., `"gui.enum.billboard.fixed": "固定"`. Untranslated keys and omitted values show the raw English token. The "Available modes" listings stay as raw tokens, since config files, commands, and the API require them verbatim. Valid values:
  * `billboard`: fixed, vertical, horizontal, center, none
  * `alignment`: left, center, right
  * `item_display_type`: none, thirdperson_lefthand, thirdperson_righthand, firstperson_lefthand, firstperson_righthand, head, gui, ground, fixed
  * `pose`: standing, fall_flying, sleeping, swimming, spin_attack, crouching, long_jumping, dying, croaking, using_tongue, sitting, roaring, sniffing, emerging, digging, sliding, shooting, inhaling

Update note: when the mod changes, don't replace your translated file. Added keys fall back to built-in English until translated; copy missing entries over from a newer `en_us.json` if you want them localized.
